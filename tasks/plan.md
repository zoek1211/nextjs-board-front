# Plan: nextjs-board-front — V1

기준 문서: [docs/SPEC.md](../docs/SPEC.md)

## 접근 방식

강의가 이미 순서와 정답 코드(`jhs512/p-14175-3` 태그)를 정해 두었으므로, 설계보다는 **재현 + 설명 작업**에 가깝다.
각 태그를 하나의 작업 단위로 보고, 아래 루프를 46번 반복한다.

### 태그 1개당 작업 루프

1. **정답 확인:** `gh api repos/jhs512/p-14175-3/compare/<이전태그>...<태그>` 로 바뀐 파일과 diff를 읽는다. 강의 페이지에서 해당 강의 설명도 함께 본다.
2. **구현:** 같은 로직을 직접 작성한다. 정답과 다르게 바꾸지 않는다 (Decision 3).
3. **학습용 주석:** 이번에 새로 등장한 개념에 "왜"를 설명하는 한국어 주석을 단다. 이전 태그에서 단 주석은 유지한다.
4. **README:** 목차에 한 줄을 추가하고, 섹션(핵심 내용 / 코드 발췌 + 설명 / `commit` 링크 · `tree` 링크)을 덧붙인다.
5. **검증:** `pnpm lint`, `pnpm build`. 데이터 연동 태그(013-1 이후)는 백엔드를 띄운 상태에서 브라우저로 화면을 확인한다. 정답 태그와 diff를 비교해 주석과 README 외에는 같은지 본다.
6. **커밋 + 태그:** `git commit -m "<태그> <설명>"` → `git tag <태그>`.

체크포인트마다 `git push origin main --tags` 로 GitHub에 올리고, 링크가 실제로 열리는지 확인한다.

## 단계와 의존 관계

모든 단계는 순차적이다. 각 태그가 이전 태그의 코드를 고치기 때문에 병렬로 할 수 있는 작업은 없다.

```
Phase 0 환경 준비 (JDK 25, 백엔드 068 실행, git/GitHub)
  └─ Phase 1  001~012   프로젝트 생성 · 레이아웃 · 홈 (기능 1: 홈)
      └─ Phase 2  013-1~021   글 목록 · 글 상세 · 타입 · apiFetch (기능 2, 3)
          └─ Phase 3  022-1~025-2   글 작성 (기능 4)
              └─ Phase 4  026-1~029   글 삭제 · 글 수정 (기능 5, 6)
                  └─ Phase 5  030~034-2   댓글 목록 · 삭제 · 작성 (기능 7, 8, 9)
                      └─ 최종 검증
```

| Phase | 태그 | 기능 | 체크포인트 |
|---|---|---|---|
| 0 | — | 환경 준비 | `curl localhost:8080/api/v1/posts` 응답, GitHub 빈 저장소 생성 |
| 1 | 001 ~ 012 | 홈, 공통 레이아웃 | 홈과 `/posts` 화면이 열리고, 상단바·푸터 레이아웃이 보임. 첫 push |
| 2 | 013-1 ~ 021 | 글 다건/단건조회 | 목록에서 글을 누르면 상세가 열림. `.env`와 `apiFetch` 적용. push |
| 3 | 022-1 ~ 025-2 | 글 작성 | 글을 작성하면 상세페이지로 이동함. push |
| 4 | 026-1 ~ 029 | 글 삭제, 글 수정 | 상세에서 삭제, 수정 폼에서 저장이 반영됨. push |
| 5 | 030 ~ 034-2 | 댓글 3종 | 댓글 목록 표시, 삭제하면 바로 사라짐, 작성하면 바로 보임. push |
| 최종 | — | — | SPEC 성공 기준 전체 확인, 태그 46개의 commit/tree 링크 점검 |

## 리스크와 대응

| 리스크 | 대응 |
|---|---|
| `create-next-app` 은 비어 있지 않은 폴더에서 실패할 수 있음 (`docs/`, `tasks/` 존재) | 스크래치패드에서 `nextjs-board-front` 로 생성한 뒤 결과물을 루트로 복사. 생성 결과를 정답 `001` 과 비교해서 맞춘다 |
| 생성기가 만든 결과(lockfile, 버전)가 정답 `001` 과 다를 수 있음 | `package.json`, `pnpm-lock.yaml`, 설정 파일은 정답 `001` 기준으로 맞추고 `pnpm install --frozen-lockfile` 로 확인 |
| JDK 25 설치 후에도 Gradle이 JDK를 못 찾을 수 있음 | `JAVA_HOME` 을 openjdk@25 경로로 지정해서 `./gradlew bootRun`. 그래도 실패하면 멈추고 보고한다 (백엔드 코드는 수정하지 않음) |
| 백엔드 H2 데이터가 테스트하면서 지저분해짐 | 강의 2강에 나오는 데이터 초기화 방법을 따른다 |
| README 링크는 push 전까지 404 | 체크포인트마다 push한 뒤 링크를 실제로 열어 확인 |
| 태그를 잘못 달았을 때 | push 전에는 로컬에서 고친다. push 후 태그를 덮어써야 하면 먼저 묻는다 (SPEC Never 항목) |
| `.env` 커밋 | 강의(20강)에서 의도적으로 커밋한다. 값은 `localhost` URL뿐이고 비밀값이 아님 |

## 빌드가 안 되는 초기 태그

`001`~`012` 는 화면 구성 단계라서 백엔드 없이 build/lint만 확인한다. `013-1` 부터는 브라우저 확인을 함께 한다.
