# Plan: nextjs-board-front — V1 + V2

기준 문서: [docs/SPEC.md](../docs/SPEC.md)

## 접근 방식

강의가 이미 순서와 정답 코드(`jhs512/p-14175-3` 태그)를 정해 두었으므로, 설계보다는 **재현 + 설명 작업**에 가깝다.
각 태그를 하나의 작업 단위로 보고, 아래 루프를 45번 반복한다. (계획 당시 46으로 잘못 셌음, 실제 태그 목록은 45개)

### 태그 1개당 작업 루프

1. **정답 확인:** `gh api repos/jhs512/p-14175-3/compare/<이전태그>...<태그>` 로 바뀐 파일과 diff를 읽는다. 강의 페이지에서 해당 강의 설명도 함께 본다.
2. **구현:** 같은 로직을 직접 작성한다. 정답과 다르게 바꾸지 않는다 (Decision 3).
3. **학습용 주석:** 이번에 새로 등장한 개념에 "왜"를 설명하는 한국어 주석을 단다. 이전 태그에서 단 주석은 유지한다.
4. **README:** 목차에 한 줄을 추가하고, 섹션(핵심 내용 / 코드 발췌 + 설명 / `commit` 링크 · `tree` 링크)을 덧붙인다.
5. **검증:** `pnpm lint`, `pnpm build`. 데이터 연동 태그(013-1 이후)는 백엔드를 띄운 상태에서 브라우저로 화면을 확인한다. 정답 태그와 diff를 비교해 주석과 README 외에는 같은지 본다.
6. **커밋 + 태그:** `git commit -m "<태그> <설명>"` → `git tag <태그>`.

체크포인트마다 `git push origin main --tags` 로 GitHub에 올리고, 링크가 실제로 열리는지 확인한다.

| `.env` 커밋 | 강의(20강)에서 의도적으로 커밋한다. 값은 `localhost` URL뿐이고 비밀값이 아님 |

# V2: 35강 ~ 51강 (태그 035 ~ 051)

기준 문서: [docs/SPEC.md](../docs/SPEC.md) V2 · 결정: SPEC "Decisions (2026-11-24, V2)"

## 접근 방식

V1과 같은 태그 루프를 24번 반복한다. V1과 다른 점은 세 가지다.

- **커밋마다 push:** 체크포인트마다 몰아서 올리지 않는다. 커밋과 태그를 만든 직후 `git push origin main <태그>`로 올리고, `commit/<태그>` 링크가 열리는지 확인한다.
- **리팩토링 구간(037 ~ 048):** 거의 모든 태그가 `src/app/posts/[id]/page.tsx` 한 파일만 고친다. 코드가 컴포넌트와 훅으로 옮겨질 때 **V1에서 단 주석도 함께 옮긴다.** 동작은 바뀌지 않아야 하므로 태그마다 같은 화면 점검(아래 "회귀 점검")을 한다.
- **README 특이 섹션:** `040`은 로직 변경 없이 README와 주석만 담는다. 45강 섹션(코드 변경 없음)은 `046-1` 커밋에 함께 넣는다.

### 태그 1개당 작업 루프 (V2)

1. **정답 확인:** `gh api repos/jhs512/p-14175-3/compare/<이전태그>...<태그>` 로 diff를 읽고, 강의 페이지의 해당 강의 설명을 본다.
2. **구현:** 정답과 같은 로직으로 작성한다.
3. **학습용 주석:** 새 개념에 "왜" 주석을 단다. 옮겨진 코드의 기존 주석은 같이 옮긴다.
4. **README:** 목차 한 줄 + 섹션(commit/tree 링크, 강의, 핵심 내용, 코드 발췌).
5. **검증:** `pnpm lint && pnpm build` → 백엔드(068)를 띄운 상태에서 브라우저 확인 → 정답 태그와 diff 비교(주석/README 제외).
6. **커밋 + 태그 + push:** `git commit -m "<태그> <설명>"` → `git tag <태그>` → `git push origin main <태그>` → `commit/<태그>` 링크 확인.

### 회귀 점검 (037 ~ 048 매 태그)

글 상세 열기 → 댓글 목록 표시 → 댓글 작성 즉시 반영 → 댓글 삭제 즉시 반영 → 글 삭제 후 목록 이동.
